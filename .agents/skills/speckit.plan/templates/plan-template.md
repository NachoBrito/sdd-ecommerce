## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- [ ] **P1 Distribution**: Single deployable maintained? (If new process/service/queue: includes written justification with valid exemption)
- [ ] **P2 Simplicity & Deletion**: Speculative abstractions rejected? Rule of Three respected? Module rewrite in <=1 day (<500 LOC)?
- [ ] **P3 Explicit Dependencies**: All dependencies injected via constructors/parameters? No global singletons or import side-effects?
- [ ] **P4 Boundary Contracts**: Explicit versioned schemas at all boundaries (HTTP/queue/file/DB)? Domain logic isolated from wire payloads?
- [ ] **P5 Testing Strategy**: Pure transformations tested with unit tests; boundaries tested with integration tests; zero mocks of internal code; failing test committed before bug fixes?
- [ ] **P6 Structured Observability**: Structured events emitted with mandatory context (timestamp, event_type, request_id, user_id, tenant_id, feature_flags)?
- [ ] **P7 Recovery & Rollback**: Revertible in <5 min without code changes? Risky paths feature-flagged? Expand-then-contract migrations?
- [ ] **P8 Alerting & Attention**: Alerts tied to user-visible symptoms with runbook links? No non-actionable alert noise?
- [ ] **P9 User Realization**: Definition of Done includes production deployment, live telemetry verification, and rollback readiness?
- [ ] **P10 Discoverable Commands**: All developer and CI workflows runnable via unified root commands (e.g. `make <target>`)?
